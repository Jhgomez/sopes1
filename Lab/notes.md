## VM vs Containers
En el contexto de publicar aplicaciones web, ya sea front end o backend nuestras apps dependen de otras apps, antes se tenia la opcion de utilizar una maquina virtual, por ejemplo VMWare en sus inicios que era puramente una maquina virtual pero ahora ya manejan contenedore, o un contender, que es lo mas comun hoy en dia. Las VM que estamos hablando son muy diferentes la VM de un lenguaje de programacion como Java, practicamente son dos cosas diferentes de las que estariamos hablando. Una VM tiene los siguientes componentes, 1. hardware/infrastructure , 2. Host OS, 3. Hypervisor, 4. Virtual machines. Containers on the other hand are lighter and that is why they are prefered their architecture is 1. infrastructure/hardware, 2. OS, 3. Docker Engine, 4. Applications we are deploying and its dependencies. A big difference is that encapsulation of VM is at hardware level while encapsulation of containers is OS level. Containers needs fewer resources and are more portable

## Docker objects
* Images: Scripts with specifications to create a container

* Container: Is an instance of an image in runtime

* Volumens: Persistent data generated by Docker are store in volumens, think of it as the hard disk, we should store databases here.

* Redes: Is a channel that containers use to communicate between each other

Docker containers can store anything, like code, services, db's, libraries

Containers are design for microservices and not monolith applications

If your database is too large your app should be able to communicate with an external DB

We can use Docker Swarn, Kubernetes or portainer to control shared access to containers

* Containers where created from a Linux concept called "namespace" which is how is called the idea of defining specific resources a set of applications has access to that way the resources a process is using doesn't interfere with the resources another process is using

* Cgroups or "control groups" is also a Linux concept that inspired the creation of containers. cgroup lets a user manage the use of resources of a process as well as the access to permissions to this processes

* Docker engine is called "Libcontainer" and is written using GO language

## What is Kubernetes?
So we can see the Docker and Kubernetes like if Docker Containers where virtual machines and Kubernetes the OS that manages those VMs.

In this case Kubernetes manages containers in what is called a Cluster, that means a cluster is a group of containers.

These cluster depend on two types of nodes, a master node and a worker node, in the worker nodes we find the application, the master node is in charge of communication between worker nodes, automation, manage all processes.

### Master Node
In the master node we can find a few services

* kube-apiserver: It communicates master node with worker nodes

* kube-scheduler: Execute scheduled tasks

* kube-control-manager: executes the cluster

* etcd: a connection to a data base

### Worker Node

Our application will be running inside a worker node, a worker node components are:

* Kubelet: Is a service that communicates with kube-apiserver, basically is the connection between nodes

* POD: inside a POD we find our app along with its dependencies installed. In a microservice architecture, each different microservice is a basically a worker node

We could scale our app using Docker and Kubernetes either horizontally or vertically, if we want to scale horizontally we just need to add more PODs or basically, more worker nodes, maybe we could have three instances of the same service meaning three worker nodes with the same service to be able to process high demand. We could also process high workloads by vertically scaling up our application, these means we would add more clusters. The best approach depends of different things

## Install Docker in Windows
You can use WSL or download a Linux distro and store it in a USB or storage drive and make it bootable wit a software like rufus and then either make a clean install or a dual boot if you want to run both operating systems

If you want to use WSL follow [this guide](https://learn.microsoft.com/en-us/windows/wsl/tutorials/wsl-containers)

These are some Docker commands you might need
* List the commands available in the Docker CLI by entering: `docker`
* List information for a specific command with: `docker <COMMAND> --help`
* List the containers on your machine, with: `docker container ls --all` or `docker ps -a` (without the -a show all flag, only running containers will be displayed)
* List system-wide information regarding the Docker installation, including statistics and resources (CPU & memory) available to you in the WSL 2 context, with: `docker info`
* Build image: `docker build -t <nombre_de_la_imagen>`
* Build image: `docker build -f <dockerFileName> -t <nombre_de_la_imagen>`
* Run image: `sudo docker run -d -p <host_port>>:<<container port>> <<image name>>`
* Run image, limits memory to 100MB, --rm says to remove when containter stops, and "free -m" says to run Linux monitoring tool as well to check how much memory it is using: `docker run -m=100m --name olinux --rm oracleLinux:8 free -m`
* Access the command line of a container that is already up: `docker exec -it <alias> /bin/sh`
* Deletes all containers, images and volumes: `docker system prune -a`
* Deletes specific container: `docker rm <<id container>>`
* Deletes specific image: `docker rmi <<id image>>`
* Forces removal of specific image:  `docker rmi -f <<id image>>`
